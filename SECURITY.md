# Security Policy

## Reporting a Vulnerability

Please do not open a public Issue for security-sensitive problems involving:

- token leakage
- account file exposure
- management password exposure
- authentication bypass
- remote code execution
- privilege escalation

Instead, report the issue privately to the maintainer through the repository contact channel or a private message path you already use with the maintainer.

When reporting, please include:

- affected version or commit
- impact summary
- reproduction steps
- logs or screenshots if safe to share
- whether the issue is already being exploited

## Handling Notes

- Please avoid posting real secrets in reports.
- If a fix requires configuration changes, document the safe upgrade path.
- Once a fix is available, a public advisory or changelog note can be added as appropriate.
